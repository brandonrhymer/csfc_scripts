# Security policy

## Reporting a vulnerability

Use **Security -> Advisories -> Report a vulnerability** in this repository to
send a private report when private vulnerability reporting is available. Include
the affected commit and script, impact, and a minimal synthetic reproduction.
Do not attach actual credentials, inventories, system logs or deployment details.

If that option is unavailable, open a public issue asking the maintainer for a
private reporting channel without disclosing the vulnerability itself. Keep
sensitive details private until an appropriate channel has been established.

## Scope and support

Reports against the current `main` revision are triaged. This policy makes no
support promise for older revisions or response time. Historical validation
does not certify a current revision or a particular environment.

These scripts perform administrative operations with materially different
effects. Use each package's documented prerequisites, scope and approved change
procedure. A successful CI run is evidence about isolated checks only, not a
security certification or authorization for operational use.
